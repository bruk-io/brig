## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
just done fails at its typecheck step on a pre-existing mypy strict error in the TIOCSTI battery:

    tests/e2e/test_tiocsti_battery.py:74: error: Incompatible return value type (got "int | None", expected "int")  [return-value]
    Found 1 error in 1 file (checked 35 source files)

The function is declared `-> int` and returns `exc.errno` from the `except OSError` branch; `OSError.errno` is typed `int | None`.

This is a semantics decision, not a drive-by typing fix. In this file 0 means "the ioctl succeeded -- the TIOCSTI escape worked", so `return exc.errno or 0` would silently grade an errno-less OSError as a successful jail escape, and a `# type: ignore` would hide the case entirely. A sentinel such as -1 is honest about "OSError with no errno" but then fails the positive control at line 158 (`assert result == errno.EPERM`), which is arguably correct -- an unexplained OSError is not evidence the probe can tell open from closed. Whoever owns rule 11's battery should pick the behaviour.

Found while confirming TASK-0001.02 (docs and architecture model): unrelated to docs, mkdocs, mkdocstrings or LikeC4. Every other step of `just done` passed in that run (ruff, pypeeker gates, the test layers, mkdocs build --strict, likec4 validate, c4lint). Because `just done` exits non-zero, TASK-0001.02 AC#6 cannot be met until this is resolved.
