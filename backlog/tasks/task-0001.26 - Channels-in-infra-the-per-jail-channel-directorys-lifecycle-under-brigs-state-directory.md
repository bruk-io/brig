## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
decision-0002 item 2's infra half: infra/sockets.py creates and removes the per-jail channel directory that TASK-0001.25's reservations point into, and presentation wires it into a jail's life. The directory is the same kind of object as the supervisor script, and three bugs that object already had must not come back: it lived in /tmp (TASK-0006), it was unreachable under some fs policies (TASK-0001.22), and it leaked when a jail failed partway or was torn down (TASK-0001.21, TASK-0012).
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 infra/sockets.py creates a per-jail channel directory under brig's state directory (never /tmp), private to the owning user, and removes it; infra imports nothing from brig and takes and returns plain data; an e2e gateway test exercises both on the real filesystem
- [ ] #2 A jail that declares channels under an FsPolicy that cannot reach the channel directory fails at create with a typed error before anything starts, through the same guard as the state directory's reachability check (generalised, not copied); an integration test pins it
- [ ] #3 The channel directory is gone after destroy, after a create that fails once the directory exists, and after a jail destroyed before it ever ran; integration tests pin each of the three
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
### Order of work
1. `infra/sockets.py` (new, infra imports nothing from brig): `create(path)` -- mkdir
   with parents, then chmod 0o700 so the leaf is private to the owning user, idempotent
   (a second `create` on an already-0700 path re-chmods to the same mode, so privacy
   holds even if something else changed the mode in between); `remove(path)` --
   `shutil.rmtree`, letting `FileNotFoundError`/`OSError` propagate (callers decide
   whether to swallow, same split as `supervisor_script.unlink`).
   `tests/e2e/test_sockets_gateway.py` exercises both for real (AC#1), the same
   test-layer placement `tests/e2e/test_state_dir.py` already uses for a pure-ish infra
   module, since `brig-test-layers` forbids a unit test importing `brig.infra` at all;
   includes one assertion that a second `create` on the same path still reads 0o700.
2. `presentation/ports.py`: grow `ChannelDirectoryPort` with `create(path)` and
   `remove(path)`, matching `infra/sockets.py`'s shape one for one.
3. `presentation/errors.py`: add `ChannelDirectoryUnreachable(channel_dir, ancestor)`,
   mirroring `StateDirectoryUnreachable`'s shape and message style.
4. `presentation/api.py`:
   - `_RealChannelDirectories` gains `create`/`remove` wired to `infra.sockets`.
   - New `_check_channel_directory_reachable(policy, state_dir, channel_dir)`: builds
     `FsPolicy(binds=(*policy.binds, Bind(host_path=state_dir, jail_path=state_dir)))`
     and calls the existing, unchanged `bwrap.covering_ancestor_bind` on it (AC#2's
     "same guard... generalised, not copied" -- no change to `domain/jail_types/bwrap.py`
     or any other domain module; the one pure function just gets a richer bind list as
     input). `compile_supervisor_launch`'s own argv order (policy binds, then the
     unconditional state_dir bind, then the channel bind) means that synthetic bind is
     always the last ancestor of any path nested under `state_dir`, so it always wins
     over anything `policy` names on its own. Refuses (raises
     `ChannelDirectoryUnreachable`) only when the winning ancestor is read-only *and*
     its own host path is not `state_dir` itself -- the one case brig cannot fix by
     creating the leaf, because the directory that would actually need the leaf
     (whatever `ancestor.host_path` really is) is not one brig owns or writes to. No
     filesystem check needed (unlike `_check_state_dir_reachable`): when the ancestor's
     host path *is* `state_dir`, brig is about to create the leaf there itself (step
     4's next bullet), so it always exists by the time bwrap runs. Called from
     `_supervisors_for`, right after `_check_state_dir_reachable`, so it only runs on
     the real path (an explicit fake `supervisors=` still means "policy plays no
     part," unchanged).
   - `create_bwrap_jail` gains `directories: ChannelDirectoryPort = _channel_directories`.
     `directories.create(channels.directory.host_path)` moves *inside* the existing
     `try`, right before `plan = bwrap.compile_run(...)` -- not after `_supervisors_for`
     and outside it as an earlier draft of this plan had it, which would leak the
     directory on a `create` that itself raises partway (mkdir succeeds, chmod fails).
     The `except BaseException` block removes it too now (swallowing `OSError`, same
     pattern as the script's `unlink`, and safe to call even when `create` never
     finished: `remove` on a path `mkdir` already created but `chmod` failed on still
     finds something to delete) before re-raising (AC#3's "after a create that fails
     once the directory exists"). `Jail` gains `channel_directory: Path | None`, set
     from `channels.directory.host_path` only once `directories.create` has actually
     returned.
   - `destroy_jail` gains the same `directories` parameter; after the existing
     `supervisor_script` cleanup, removes `jail.channel_directory` the same way
     (swallowing `OSError`) -- covers both "gone after destroy" and "gone after a
     jail destroyed before it ever ran" (AC#3: two call sites, not three -- the
     "destroyed before it ever ran" case falls out of the first for free, since
     `channel_directory` rides on `Jail` regardless of whether `run_jail` ran).
5. `tests/integration/fakes.py`: `FakeChannelDirectories` gains `created`/`removed`
   lists and `create`/`remove` methods (bookkeeping only, never touches a real path).
   `FakeSupervisors` gains `fail_start: bool = False`, making `start` raise `OSError`
   -- `run()` (`presentation/drivers/bwrap.py`) already turns that into
   `JailSpawnFailed`, the fakes-only way to exercise AC#3's "create that fails" case
   (this path runs through `run()`, inside the widened `try`, so it is already
   covered by the corrected ordering above).
6. `tests/integration/test_channel_reservations.py`: thread the same
   `FakeChannelDirectories` instance into `create_bwrap_jail`/`destroy_jail` (not just
   `reserve_channels`) -- without this, the new default `directories` parameter would
   call the real `infra.sockets.create` against the fake's `/fake/state/channels/0001`
   path and fail outright.
7. New `tests/integration/test_channel_directory_lifecycle.py`: AC#3's two call sites
   (destroy after run; destroy with no preceding run_jail) plus the create-that-fails
   case, each against `FakeChannelDirectories`/`FakeProcesses`/`FakeSupervisors` --
   `removed` names the right path after an ordinary destroy, after `destroy_jail` with
   no preceding `run_jail`, and after `create_bwrap_jail` raises `JailSpawnFailed`
   (`fail_start=True`) once `created` already names the directory.
8. New `tests/integration/test_channel_directory_reachability.py`: AC#2, through the
   real default `supervisors`/`processes` (so `_supervisors_for` actually runs) with
   `BRIG_HOME` pointed at a per-test tmp dir, and a fake `directories` (legitimate
   alongside real `supervisors`/`processes`: the guard reads `policy`, never the
   port) so the assertion is "the guard raised/did not raise" and "`directories.create`
   was/was not reached," not entangled with real bwrap availability. One case names a
   read-only `Bind` ancestor of the channel directory whose host path is not
   `state_dir` -> `ChannelDirectoryUnreachable`, raised before `directories.create` or
   the supervisor-script write ever run (`fake.created == []`). A second asserts the
   ordinary default policy (`WHOLE_HOST_READ_ONLY`) does not raise and does reach
   `directories.create` (`fake.created == [path]`) -- proof AC#2's guard does not
   false-positive on the common case; stops short of calling `run_jail` so it needs no
   real bwrap either way.

Implementation note carried from TASK-0001.25's review (finding 2, "reserve_channels
picks the directory before it validates names"): moot under this design.
`ChannelDirectoryPort.allocate()` still only *names* a path (TASK-0001.25, unchanged);
real creation happens later, in `create_bwrap_jail`, only once `reserve`'s own name
validation already succeeded. A refused name raises `ChannelNameRefused` straight out
of `reserve_channels`, before `create_bwrap_jail` -- and therefore `directories.create`
-- is ever reached, so nothing is ever created to leak.

### Risks
- The reachability guard's correctness rests on `compile_supervisor_launch`'s current
  argv order (policy binds, then the unconditional `state_dir` bind, then the channel
  bind) always holding -- captured as a cross-reference in both docstrings, not
  re-derived from bwrap's own behaviour a second time, so a future reordering there is
  a silent correctness break here rather than a loud one. No new domain code or unit
  test added for it beyond that cross-reference, since the logic is just an input
  (the augmented bind list) to the already-fully-unit-tested `covering_ancestor_bind`.
- `ChannelDirectoryPort` is injectable at `reserve_channels`, so a caller's own
  directory need not live under `state_dir` at all -- the guard still answers
  correctly for that case (falls through to whatever `policy` alone says), but no
  test here should assume every channel directory is `state_dir`'s own child.
- Wiring `directories.create`/`remove` through the port unconditionally (not only on
  the real path) changes `create_bwrap_jail`/`destroy_jail`'s observable behaviour for
  every existing caller that declares channels -- `test_channel_reservations.py` must
  be updated in the same change, not after, or it breaks by touching a real,
  non-existent `/fake/...` path.
- Removal must be `shutil.rmtree`, not a bare `rmdir`: the jailed command creates real
  sockets inside the directory before destroy ever runs.
- `directories.create` can fail partway (mkdir succeeds, chmod does not) -- it must run
  inside `create_bwrap_jail`'s existing `try`, with its own cleanup in the matching
  `except`, or that partial state leaks exactly like AC#3's second case describes.

### Proof

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Split from TASK-0001 for channels (decision-0002 item 2). Depends on TASK-0001.25 because the wiring in presentation/api.py needs the domain's Reservation and the directory path it derives; running them in parallel would collide in api.py.

From TASK-0001.25's review (2026-10-19), findings that land here: (1) the default ChannelDirectoryPort names <state_dir>/channels/<token> but does not create it, so a real bwrap jail that declares channels fails until this task creates the directory (bwrap would try to make the mountpoint under the read-only state-directory bind); also confirm the writable channel bind inside the read-only state-dir bind is actually writable in a real jail. (2) reserve_channels picks the directory before it validates names, so once picking creates the directory, a refused name must not leak it: check names first or remove the directory on refusal. AC#3's spirit (the directory is gone after a create that fails once it exists) already covers this; the refused-name path is one more such failure.
