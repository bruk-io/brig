## Implementation Plan

### Order of work

1. decision-0001 amendment: rule 6's `init-reexport-only` -> `barrel-only` (the pypeeker builtin
   that actually exists). pypeeker is a dev dependency on git `main`, unpinned (owner's choice);
   custom rules are written against `pypeeker.dsl.register_dsl_rule`, the only authoring surface
   still alive on `main` (the legacy `register_rule` the pypeeker-gate skill documents was deleted
   there in pypeeker's "phase-5 flip").
2. pyproject.toml: uv project, Python >=3.15, no runtime deps; ruff (DOC501/DOC502, preview on);
   mypy strict; pytest; dev group with `rust-just==1.59.0`, `pypeeker` (git, branch main), bare
   `mkdocs` (for step 7); base `[tool.pypeeker]` (`src = ["src", "tests"]`,
   `plugins = ["pypeeker_rules.brig"]`). `uv sync`.
3. Empty layers: `src/brig/{domain,infra,presentation}/__init__.py`, `src/brig/__init__.py`;
   `tests/{unit,integration,e2e}/`, `tests/integration/fakes.py` stub.
4. The gate: enable the 5 house-rule builtins (`barrel-only`, `under-exposed-access`,
   `over-exposed-module-symbol`, `import-time-side-effects`, `no-import-cycles`); write
   `pypeeker_rules/brig.py` with the 8 brig-prefixed custom DSL rules (`brig-layers`,
   `brig-pure-domain`, `brig-slices`, `brig-test-layers`, `brig-no-patching`, `brig-class-forms`,
   `brig-vocabulary`, `brig-one-writer`); one planted-violation test per custom rule in
   `pypeeker_rules/tests/` (outside `tests/` entirely, since these test the lint config, not brig -
   each writes a tmp_path fixture tree and runs an isolated `pypeeker index` + `check --strict`
   subprocess against it). Confirm clean against the real skeleton.
5. justfile: `check`, `gates` (index + `check --strict`), `done` (ruff, mypy, gates,
   unit+integration x2+e2e, docs build, arch lint - whole report, failures collected, unrunnable
   e2e listed by name).
6. scripts/: `affected_tests.py` (diff-against-main + uncommitted/untracked -> reached
   unit/integration tests, via `pypeeker refs --all`); `run_done.py` (the step runner `just done`
   calls).
7. CI: `.github/workflows/ci.yml` - ubuntu-latest, `apt-get install bubblewrap` (Docker is already
   on the runner), setup-uv, `uv sync`, `uv run just done`.
8. Docs/arch placeholder, built by a background agent in parallel with steps 4-7 once step 2 has
   landed: root `mkdocs.yml`, `docs/index.md`, a minimal real `docs/architecture/` LikeC4 System
   Context view - genuinely passing `mkdocs build --strict` and the c4-architecture plugin's
   c4lint, not a no-op. Told explicitly not to name any embedder (AC#16) and not to touch
   pyproject.toml, justfile, scripts, or CI.
9. Settle TASK-0001's open question on the ruff-on-edit hook: no hook, ruff runs only in
   `just done` (the intent's own words). Tick it, replace its "Carried forward" line.
10. Full verification pass (below), push, confirm CI green.

### Risks

- Tracking pypeeker's `main` means no version boundary if gate behaviour shifts;
  `register_dsl_rule` is not one of pypeeker's three declared-frozen contracts either, just the
  only plugin surface currently alive.
- `brig-class-forms` (classifying every class into exactly one of 4 allowed shapes) and
  `brig-no-patching` (catching a `monkeypatch` fixture *parameter*, not just a mock import) are the
  hardest of the 8 custom rules to express correctly and the most likely to need iteration.
- `brig-test-layers` needs its own asymmetric rule (unit->domain only; integration->public API +
  fakes; e2e->public API or one infra module); pypeeker's `import-boundaries` builtin can't express
  that shape, so this is hand-written DSL, not a second builtin instance.
- CI's `apt-get install bubblewrap` assumes the GitHub-hosted Ubuntu image still lacks it; worth
  confirming rather than assuming.
- The background agent and the main thread both touch this repo concurrently; the agent is scoped
  to docs/architecture files only to avoid colliding with pyproject.toml, justfile, scripts, or CI.

### Proof

- `uv sync` clean; `just --list` shows every recipe.
- Each of the 8 planted-violation tests demonstrates its rule firing.
- `pypeeker index src tests pypeeker_rules && pypeeker check --strict` clean on the real skeleton.
- `just check` selects only reached tests against a dummy touched file.
- `just done` green locally, including the docs/arch steps once the background agent lands.
- GitHub Actions runs `just done` and goes green.
- `board-check plan TASK-0001.01` passes once committed.
