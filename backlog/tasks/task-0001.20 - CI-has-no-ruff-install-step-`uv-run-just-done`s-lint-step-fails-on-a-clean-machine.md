## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found while verifying TASK-0001.15 step 5's tests on real Linux (a fresh `ubuntu:24.04` --privileged container, mirroring `.github/workflows/ci.yml`'s own steps exactly: `uv sync` then `uv run just done`, nothing else installed up front).

`pyproject.toml`'s `[dependency-groups].dev` has no `ruff` entry (checked back to the scaffolding commit, `f43c40f` -- not something this session's own changes removed), and `.github/workflows/ci.yml`'s one job runs only `uv sync` then `uv run just done`, with no separate ruff install step. `just lint` (and so `just done`, and so CI) invokes `uv run ruff check .` / `uv run ruff format --check .` directly.

On a developer's own machine this is invisible, because `ruff` is installed globally as a `uv tool` (outside the project's own dependency tree) and `uv run` falls through to it on `$PATH`. On a clean machine with no such global install -- a fresh CI runner, or this task's own disposable verification container -- `uv run ruff check .` fails with `error: Failed to spawn: ruff / cause: No such file or directory`, before any test ever runs.

TASK-0001.12's own review already noted "the repo still has no git remote, so CI has never run" -- so this gap has not yet been hit for real, but would be the first thing CI fails on the moment it does.

Reproduced directly: `docker run --platform linux/amd64 --privileged ubuntu:24.04`, `uv sync`, `uv run ruff check .` -&gt; `Failed to spawn: ruff`. Installing `ruff` as a `uv tool` (not a project dependency) in the same container made it pass, confirming the fix: `ruff` needs to be a real project dependency (or `uv.lock`-pinned dev tool), not assumed present on `$PATH`.
<!-- SECTION:DESCRIPTION:END -->
