## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
### Order of work

1. domain/effects.py: add StartSupervisedCommand (argv, env -> Process) and AwaitSupervisorDone
   (process, deadline -> ExitOutcome, mirroring reap_deadline's ExitCodeUnknown-vs-timeout
   honesty). Keep Verify/SignalGroup for teardown's TERM/KILL escalation.
2. infra/supervisor/wire.py: the message shapes (newline-delimited JSON): one exec request in
   (argv, env); started/exited/done events out. program.py: forks the real command as its own
   child, reaps everything reparented to it as PID 1 (including orphans), emits done once
   nothing remains. Settle DRAFT-0009 AC#3 here, empirically: try importing wire.py's message
   encode/decode from link.py directly first (same process, same package, simplest); fall back
   to a duplicated minimal encoder only if assembling wire.py+program.py into one file (rule 17)
   turns out to make that import impossible from the host side. Record the actual answer, not a
   guess, in this task's notes.
3. infra/supervisor/link.py: the host's end -- starts the assembled file via the existing
   infra.processes.spawn, speaks the wire protocol, exposes a plain-data interface
   presentation's driver can call.
4. presentation/drivers/bwrap.py: perform StartSupervisedCommand/AwaitSupervisorDone by calling
   link.py through a port; presentation/ports.py gains the Protocol for it.
5. One unit test (drive program.py's reap-everything-as-PID-1 logic by hand, no real jail
   needed -- it's just a process-management loop); one integration test (a fake supervisor
   link, proving the journey through the public API with no real subprocess); one e2e test
   (real bwrap jail through the real supervisor, skip-guarded on this macOS host, runs for real
   in CI on Linux).
6. Confirm the walking skeleton's existing happy path (create/run/destroy "true") still works
   end to end through the new supervised path, not just in isolation.

### Risks

- This is the biggest architectural change since the walking skeleton itself: it changes what
  the host actually waits on for every jail, not just adds a feature. Expect the existing
  teardown/group-probing code (TASK-0001.06/.07/.08/.09's hardening) to become substantially
  simpler once this lands -- that's expected, not a regression to prevent.
- DRAFT-0009's sharing question is genuinely open; step 2 settles it empirically rather than
  by further argument.
- `rule 17`'s "assembled... stdlib only" constraint means wire.py/program.py cannot import
  anything from brig itself once dropped as the PID-1 file -- double-check nothing in them
  reaches back into brig.domain/infra/presentation.
