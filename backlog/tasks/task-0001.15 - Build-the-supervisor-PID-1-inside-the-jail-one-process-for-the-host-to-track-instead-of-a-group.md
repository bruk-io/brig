## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
### Order of work

1. domain/effects.py: add StartSupervisedCommand (argv, env -> Process) and AwaitSupervisorDone
   (process, deadline -> ExitOutcome, mirroring reap_deadline's ExitCodeUnknown-vs-timeout
   honesty). Keep Verify/SignalGroup for teardown's TERM/KILL escalation.
2. infra/supervisor/wire.py: the message shapes (newline-delimited JSON): one exec request in
   (argv, env); started/exited/done events out. program.py: forks the real command as its own
   child, reaps everything reparented to it as PID 1 (including orphans), emits done once
   nothing remains. Settle DRAFT-0009 AC#3 here, empirically: try importing wire.py's message
   encode/decode from link.py directly first (same process, same package, simplest); fall back
   to a duplicated minimal encoder only if assembling wire.py+program.py into one file (rule 17)
   turns out to make that import impossible from the host side. Record the actual answer, not a
   guess, in this task's notes.
3. infra/supervisor/link.py: the host's end -- starts the assembled file via the existing
   infra.processes.spawn, speaks the wire protocol, exposes a plain-data interface
   presentation's driver can call.
4. presentation/drivers/bwrap.py: perform StartSupervisedCommand/AwaitSupervisorDone by calling
   link.py through a port; presentation/ports.py gains the Protocol for it.
5. One unit test (drive program.py's reap-everything-as-PID-1 logic by hand, no real jail
   needed -- it's just a process-management loop); one integration test (a fake supervisor
   link, proving the journey through the public API with no real subprocess); one e2e test
   (real bwrap jail through the real supervisor, skip-guarded on this macOS host, runs for real
   in CI on Linux).
6. Confirm the walking skeleton's existing happy path (create/run/destroy "true") still works
   end to end through the new supervised path, not just in isolation.

### Risks

- This is the biggest architectural change since the walking skeleton itself: it changes what
  the host actually waits on for every jail, not just adds a feature. Expect the existing
  teardown/group-probing code (TASK-0001.06/.07/.08/.09's hardening) to become substantially
  simpler once this lands -- that's expected, not a regression to prevent.
- DRAFT-0009's sharing question is genuinely open; step 2 settles it empirically rather than
  by further argument.
- `rule 17`'s "assembled... stdlib only" constraint means wire.py/program.py cannot import
  anything from brig itself once dropped as the PID-1 file -- double-check nothing in them
  reaches back into brig.domain/infra/presentation.

### Proof

- just gates, just typecheck clean.
- All three new tests pass; the e2e one is a real journey through a real bwrap jail on Linux
  (reported, not run, on this macOS host -- per the e2e rule).
- just done green.
- The walking skeleton's existing integration/e2e tests still pass unmodified in spirit (may
  need updating to go through the new supervised path, but the behavior they assert must not
  regress).

Step 3 (link.py, the host's end) done.

Added src/brig/infra/supervisor/link.py: `_start(supervisor_argv, command_argv,
env) -> _Supervisor` starts the assembled wire.py+program.py file through
`infra.processes.spawn` (never a separate posix_spawn call of its own, so
TASK-0001.08/.09's hardening -- the setsid/setpgroup fallback, the EBADF
close-action retry -- covers the supervisor's own start too), wires its stdin
and stdout to two pipes this process owns, writes the one exec request, and
hands back `_Supervisor`, whose `read_event()`/`close()` decode the
started/exited/done stream. Everything new is leading-underscore
(`_SupervisorSpawnError`, `_Supervisor`, `_start`): no caller outside this
module exists yet, since presentation/drivers/bwrap.py's own wiring (step 4)
isn't written. Drop the underscores there.

Added two stdin_fd/stdout_fd keyword parameters to infra/processes.py's
`spawn` (not in this task's original modified_files list -- added here, and
the change is this: `spawn` had no way to give a new process its stdin/stdout
from a fd of this process's own instead of the ordinary inherited stream, and
link.py genuinely needs that for the wire protocol's two pipes. The
alternative -- a second, separate posix_spawn call inside link.py -- was
rejected: it would either duplicate TASK-0001.08/.09's measured hardening or
silently lack it, and link.py is the path every jail will take from now on.
Implemented as one `os.POSIX_SPAWN_DUP2` file action per side given, each
followed by closing the original fd number in the new process (unless it
already is 0/1) -- ordered after the existing close-the-rest-of-inheritable
actions, with the two redirect fds explicitly protected from that same close
pass (`_close_actions`'s new `protect` parameter), stated explicitly rather
than relying on `os.pipe()`'s fds being non-inheritable by default. `just
typecheck`/`just gates` both stay clean against this change alone.

Follow-up fix to `_start` (same step, caught in review before reporting): the
original version left `events_read_fd` unclosed and the spawned supervisor's
pid unreaped if writing the one exec request failed (EPIPE: a supervisor_argv
that execs and dies immediately, before the write) -- the `with` around the
write already closed `request_write_fd` on that path, but nothing closed the
other pipe's read end or collected the now-dead supervisor's exit status,
since no `_Supervisor` exists yet to own either at that point. Fixed: the
write is now inside its own try/except OSError, closing `events_read_fd` and
best-effort-reaping `spawned.pid` before raising `_SupervisorSpawnError`.
Verified `BrokenPipeError` (what a write past a fully-closed read end raises)
is an `OSError` subclass, so the new except clause catches it; a forced
subprocess-level repro of the exact race was attempted but not reliable
(python interpreter startup latency outpaces the write before a child can
close its own stdin), so this is confirmed by direct mechanism check rather
than a flaky race test. `just gates`/`just typecheck`/`just lint` re-run
clean after this fix, and the earlier manual end-to-end round-trip (started/
exited/done through the real program.py) still passes unchanged.

Step 5 (tests) done.

Three new tests, not quite the three layers the plan named -- settled empirically, not by further argument, the same discipline DRAFT-0009's sharing question was settled with. The plan's item 1 ("a unit test driving program.py's reap-everything-as-PID-1 loop by hand") cannot live in `tests/unit/`: `program.py` is `brig.infra`, and running a throwaway probe import through `pypeeker check --strict` confirmed `brig-test-layers` refuses `tests/unit/` importing anything outside `brig.domain`, full stop, with no allow-list escape hatch in that rule's own implementation. `under-exposed-access` separately refuses reaching into `program.py`'s own `_name`s (`_reap_until_gone`, `_start_child`) from any test layer, not only `tests/unit/` -- also confirmed the same way. Calling those functions in-process from a test would also have been unsafe regardless of layer: `_reap_until_gone` is `while True: os.waitpid(-1, 0)`, which reaps *any* outstanding child of the calling process -- called from inside a shared pytest process (this suite's own e2e file forks ptys, spawns many children, and `just done` runs integration twice in the same process) it would steal other tests' own exit statuses, reproducing exactly the ECHILD races TASK-0001.06/.08 fixed, or hang.

What landed instead, covering the same ground:
- `tests/e2e/test_supervisor_program_gateway.py`: decision-0001 rule 4's own gateway-test allowance (`test_processes_gateway.py`'s house precedent) -- runs the real `program.py` file as a real subprocess, speaking its wire protocol over real pipes with no bwrap and no namespace, across three shapes (clean exit, non-zero exit, signal-killed). This is the "no real jail needed, just the process-management logic" half of the plan's own description, just not in `tests/unit/`.
- `tests/e2e/test_supervisor_reaps_orphans.py`: the namespace-dependent half the gateway test structurally cannot reach (outside a real PID namespace, a grandchild reparents to the host's own init, never to a process that merely spawned its parent) -- a real bwrap jail, `--as-pid-1` included, where the directly-started command forks a child and exits immediately; asserts `run_jail` does not return until the orphan is also reaped (wall-clock, since no event names an orphan at all) and that the tracked child's own exit code (5) still comes through unchanged. Skip-guarded on bwrap; ran for real against real bwrap in a `--privileged ubuntu:24.04` Docker container.
- `tests/integration/test_destroy_without_run.py`: a real gap `test_walking_skeleton.py`'s re-pointed journey does not cover -- `destroy_jail` called with `run_jail` never having run at all, pinning `api.py`'s own `destroy_jail` docstring claim (`supervisors.close` runs unconditionally, not only as a no-op after `await_done` already closed it) with `FakeSupervisors`.

Real regression found and fixed while confirming the existing walking-skeleton/battery tests still pass through the supervised path, measured in the same Docker container: `tests/e2e/test_tiocsti_battery.py::test_tiocsti_injection_fails_in_a_real_bwrap_jail` failed (`assert 125 == 101`) for exactly the reason DRAFT-0010's own TASK-0001.15-step-4 update already recorded -- the supervised command's fd 0 is now the exec-request pipe (closed), not a tty, so the probe's `ioctl` fails `ENOTTY`, unrelated to confinement. ### AC#1 remaining-work addendum (plan drift, same discipline as DRAFT-0009's own settlement)

The original plan's step 2 covered wire.py/program.py's own content but not the
assembly artifact itself. Scoping that explicitly now, since it's the one thing
left before this task closes:

**Design**: program.py already duplicates wire.py's shapes/constants rather than
importing them (DRAFT-0009 AC#3, already settled) -- so the two files' source can
be concatenated safely with no name collisions (wire.py's public names vs.
program.py's leading-underscore duplicates) and no runtime dependency between them.
The delivered file is a small, maximally-portable preamble (plain `sys.version_info`
check, `sys.stderr.write`, `sys.exit` -- no 3.12+ syntax) that refuses to proceed
under Python < 3.15, followed by wire.py's source + program.py's source,
base64-encoded and `exec(compile(...))`'d only after the version check passes.
Base64 avoids any escaping hazard from the two files' own triple-quoted docstrings;
deferring the exec until after the version gate is what actually makes the "refuses
an older interpreter, saying which it needs" half of rule 17 true -- a plain
top-level concatenation would fail with a bare SyntaxError under <3.12 (wire.py's
`type Event = ...` statement) before any guard code ever ran, since Python parses
a whole module before executing any of it.

**New module**: `src/brig/infra/supervisor/assemble.py` -- `assembled_source() ->
str` (reads wire.py+program.py's own source via their `__file__`, renders the
preamble + base64 body); the version-refusal message built from a small pure
function (`_refusal_message(installed: tuple[int, ...]) -> str`), unit-testable
directly with synthetic version tuples, not only through a real old interpreter.

**presentation/api.py**: `_SUPERVISOR_PATH` becomes a lazily-assembled, cached
path (one `tempfile.NamedTemporaryFile(delete=False)` write per process,
`functools.cache`'d) rather than today's eager top-level tuple pointing straight
at `program.py`'s own file -- writing a file is real I/O, and `pyproject.toml`'s
own `[tool.pypeeker.import-time-side-effects]` allow-list has no entry for this
module, so doing it eagerly at import time would trip that rule, not just style.
`_SUPERVISOR_ARGV`/`_live_supervisors`/`_supervisors` become lazy in the same step,
since they're derived from it.

**Tests**: one confirming the assembled file's content is exactly wire.py's source
plus program.py's source (so it fails the moment either drifts without
re-assembling -- always generated fresh, never a second checked-in artifact to go
stale); one confirming it imports nothing outside the stdlib (ast-walk every
Import/ImportFrom); the version-refusal message's pure function tested directly;
one e2e test running the real assembled file as a real subprocess under whatever
older python3 interpreter this host happens to have (pyenv/system), skip-guarded
with the measured reason if none is found -- the same "measured, not argued"
discipline as every other platform-dependent battery in this suite.
