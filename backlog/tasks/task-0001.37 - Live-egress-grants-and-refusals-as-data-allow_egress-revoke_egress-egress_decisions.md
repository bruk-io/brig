## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
decision-0009 items 5, 6 and 8. allow_egress(jail, destination) and revoke_egress(jail, destination) change the running proxy's allow list over the supervisor link without a restart; egress_decisions(jail) yields one value per decision (allowed or refused, destination, time); the proxy writes each decision as one JSON line in brig's envelope (criterion 15); the report states the policy as created and every change since, and the network claim with an EgressPolicy reads 'reaches only the destinations the policy grants, only through the proxy', capped by TASK-0043's socket half and naming the CONNECT/SNI and payload gaps.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 e2e: a destination refused, then allowed with allow_egress, is reached on the next connection without restarting the jail; revoke_egress refuses the next one
- [ ] #2 e2e: each decision reaches egress_decisions with its destination and verdict, and its JSON line is in the envelope
- [ ] #3 The report and the network claim text say what decision-0009 item 8 says, held by the report battery

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
### Design
Approach: the proxy's config pipe (fd 3) carries one change per line after the first; a second pipe (the proxy's fd 5) carries one envelope line per decision back to the link, which keeps a bounded buffer. The `Jail` gains an `EgressPort`, through which the three new API calls and the report reach the running proxy. Without an `EgressPolicy`, nothing changes.

**Grant changes on a running jail.**
- **The calls:** `allow_egress(jail, destination)` and `revoke_egress(jail, destination)`.
  - A jail made without an `EgressPolicy` (`jail.egress is None`) refuses both with `JailHasNoEgress`, which says to create the jail with `egress=EgressPolicy(...)`. The jail is checked first.
  - Then the destination is validated through `check_egress_policy(EgressPolicy((destination,)))`, so the same six errors apply.
  - Once the proxy has ended (the command finished, or `destroy_jail` ran), both raise `JailEgressEnded`, and nothing is recorded.
- **How a change applies:** one pure function in `domain/policy/egress.py`, `egress_after(policy, kind, destination)`. `ALLOW` appends the destination unless it is already there. `REVOKE` removes every equal entry. The proxy runs this module's source, so the host's record and the proxy's list come from one definition.
- **The wire:** each change is one JSON line on fd 3, `{"kind", "host", "port"}` (a closed TypedDict). It is written whole under a lock in `RunningProxy.change`, which also records it with its time. A validated destination makes a line far shorter than `PIPE_BUF`, so each write is atomic.
- **What "the next connection" means:** the proxy's main loop handles fd 3 before fd 4 on every turn, and it takes the policy in force when it receives a connection's fd. Every connection the supervisor hands over after a change was written is therefore decided against the new list.
  - A connection already relaying is never judged again: revoking leaves it open.
  - A connection received but not yet decided keeps the list it arrived under.
  - Both are stated in the docstrings and the spec.

**Decisions back to the embedder.**
- **The route:** a second pipe, the proxy's fd 5 (`program.DECISIONS_FD`). The proxy's fds 1 and 2 stay `/dev/null`, so only the encoder ever writes on it.
- **The reader:** in `infra/proxy/launch.py`, a reader thread owned by `RunningProxy` drains fd 5 into a `deque`.
  - **Why a thread:** if the proxy wrote to a pipe nobody read, a quiet embedder would fill the pipe, and the proxy, with every connection it serves, would block.
  - **Why non-blocking:** `egress_decisions(jail)` drains what has arrived and returns an iterator over it. It never blocks. Each decision is yielded once, by the first call after it arrived.
  - **Why not a cursor:** a cursor would mean keeping history for a reader that may never come, which is the memory this must bound. The embedder that wants the history keeps what it took.
- **The bound:** at most 1024 undelivered lines, each at most 4 KiB, so at most 4 MiB per jail.
  - Past 1024, the oldest line is dropped.
  - A longer line is dropped whole.
  - Each decision carries the proxy's `seq` (1, 2, ...), so a drop shows as a gap.
- **Lifetime:** `RunningProxy.end` joins the reader thread after the proxy is reaped. The pipe reaches end of file then, so no thread is left (the existing battery checks this). What was read stays drainable after the end.
- **The value:** `EgressDecision(seq, verdict, destination, reason, time, line)`, in a new domain module, `domain/policy/egress_record.py`.
  - `verdict` is `EgressVerdict.ALLOWED` or `REFUSED`.
  - `reason` is `EgressReason`: granted, not-granted, unresolved, address-unparseable, private-address, authority-unparseable. These come from one pure function, `egress_reason(outcome)`, in `egress.py`, which the proxy calls.
  - `time` is an aware UTC `datetime`.
  - `line` is the envelope line verbatim, for an embedder that keeps its own log.
- **What counts as a decision:** every call the proxy makes to `decide_egress` that settles, so one per connection that named a destination. A request whose destination could not be read is answered `400` and makes no decision line, since it names no destination.

**One JSON line per decision.**
- **The envelope:** `infra/log.py` (decision-0001's layout) is new: brig's one envelope and its encoder (TASK-0001 criterion 15).
  - **The fields, in order:** `time` (RFC 3339, UTC, microseconds, `Z`), `level` (a `Level` StrEnum: debug, info, warning, error), `source`, `event`, then the event's own fields.
  - **`encode`** refuses an event field named like an envelope field, and a naive time.
  - **`decode`** reads a line back into a frozen `Line`.
  - **`write`** is the one raw-fd writer.
- **The gates:** standard library only, and it imports nothing of brig. It goes on the `brig-standalone-programs` list and on `brig-one-writer`'s allow list, which decision-0001 rule 14 names. The proxy assembler adds it to the proxy's file as a third module, `brig_log`, handed to `_main` with the decision.
- **The decision line:**
  - **Envelope:** `source` is `"egress-proxy"` and `event` is `"egress-decision"`.
  - **Fields:** `seq`, `verdict`, `host`, `port`, `reason`, a closed TypedDict in the program.
  - **Level:** `info` when allowed, `warning` when refused.
- **Where it goes:** to the proxy's fd 5, a pipe the link reads into the jail's state. From there `egress_decisions` hands the line to the embedder with each value. The library writes it nowhere: no stderr, no file.

**The report.**
- **The claim:** `bwrap.ceilings(..., egress=True)` states `NETWORK_EGRESS_CLAIM` in place of `NETWORK_CLAIM`. Its name is still `network`, and its ceiling is the same `_socket_reach` (TASK-0043's socket half).
- **Its text:** "the command reaches only the destinations the policy grants, and only through the proxy". It then names the cap: a host socket the jail can dial. It names two gaps:
  - an HTTP `CONNECT`'s authority is judged, never the TLS SNI inside it, so a granted CDN can front for another name;
  - the bytes inside a granted connection are not inspected.
- **The history:** `egress_record(jail)` returns `EgressRecord(created, changes)`, or `None` without egress. `EgressChange` holds a kind, a destination and a time. `render(report, egress=None)` adds one line for the policy as created, and one line per change since.
- **The battery:** the report battery holds the egress claim to what it measures. The positive control is a granted name reached through the proxy. The violation is an ungranted name and a direct dial, both blocked. The battery also checks the claim text and the rendered history.

### Risks
- **A reader thread per jail with egress:** joined at `end`, and the battery's thread check already covers it.
- **A partial config line:** writes are short and atomic, and the proxy buffers a partial line anyway.
- **Concurrent allow and close:** one lock in `RunningProxy` around the fd, `change` and `end`.
- **A proxy that died:** `change` hits `EPIPE` and raises `JailEgressEnded`, failing closed.
- **Size:** if the proxy or the link change grows past this plan, split it: the envelope and decision lines as one change, live grants and the report as the next.

### Proof

  - `late.test` is refused (403);
  - after `allow_egress`, it is reached on the next connection, with the same jail pid and no restart;
  - after `revoke_egress`, the next connection is refused, while a tunnel opened before the revoke still relays;
  - `egress_decisions` yields one value per decision, with destination, verdict, reason and seq;
  - each value's `line` decodes with the envelope's fields first, in order;
  - after the command finished, `allow_egress` raises `JailEgressEnded`.
- **Integration:** a jail without egress refuses all three calls with `JailHasNoEgress`; a malformed destination is refused before the port is touched.
- **The report battery:** as in the report section above.
