## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`just typecheck` (mypy strict) fails, so `just done` exits non-zero:

    tests/e2e/test_tiocsti_battery.py:74: error: Incompatible return value type (got "int | None", expected "int")  [return-value]

`_tiocsti_injection_result()` is declared `-> int` and returns `exc.errno` from its `except OSError` branch; the stdlib stub types `OSError.errno` as `int | None`.

Pick the behaviour deliberately -- this is a semantics decision, not a drive-by typing fix. In this file `0` is the sentinel for "the ioctl succeeded, the TIOCSTI escape worked", so `return exc.errno or 0` would silently grade an errno-less OSError as a successful jail escape, and `# type: ignore` would hide the case entirely. A sentinel such as `-1` is honest about "OSError with no errno" but then fails the positive control at line 158 (`assert result == errno.EPERM`) -- arguably the right outcome, since an unexplained OSError is not evidence the probe can tell an open escape from a closed one. Whoever owns rule 11's battery decides.

Every other step of `just done` passes: ruff, pypeeker gates, the test layers, `mkdocs build --strict`, `likec4 validate`, c4lint. TASK-0001.02 AC#6 ("just done runs the docs build and the architecture lint") cannot be met until this is resolved.
