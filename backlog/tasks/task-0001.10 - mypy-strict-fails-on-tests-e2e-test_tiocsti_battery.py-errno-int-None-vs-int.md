## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`just typecheck` (mypy strict) fails, so `just done` exits non-zero:

    tests/e2e/test_tiocsti_battery.py:74: error: Incompatible return value type (got "int | None", expected "int")  [return-value]

`_tiocsti_injection_result()` is declared `-> int` and returns `exc.errno` from its `except OSError` branch; the stdlib stub types `OSError.errno` as `int | None`.

The likely fix is to narrow it explicitly -- assert/raise when `errno` is None, or widen the return type to `int | None` and let the call sites handle it -- so `just typecheck` and `just done` are clean again.

Pick the behaviour deliberately, though: this is a semantics decision, not a drive-by typing fix. In this file `0` is the sentinel for "the ioctl succeeded, the TIOCSTI escape worked", so `return exc.errno or 0` would silently grade an errno-less OSError as a successful jail escape, and `# type: ignore` would hide the case entirely. A sentinel such as `-1` is honest about "OSError with no errno" but then fails the positive control at line 158 (`assert result == errno.EPERM`) -- arguably the right outcome, since an unexplained OSError is not evidence the probe can tell an open escape from a closed one. Whoever owns rule 11's battery decides.

Found twice while verifying `just done` for TASK-0001.02 (docs and architecture model); unrelated to docs, mkdocs, mkdocstrings or LikeC4, so filed here rather than expanding that task. Every other step of `just done` passes: ruff, pypeeker gates, the test layers, `mkdocs build --strict`, `likec4 validate`, c4lint.
