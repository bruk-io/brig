## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The old brig (old SPEC decision-168) bound every existing directory between a writable root and a write deny or mask over itself, so rename(2) inside the jail fails with EBUSY. compile_mounts does not: inside a writable root W with a deny at W/a/b/f, the jailed process can rename W/a (or W/a/b) away and create its own W/a/b/f, which the host reads once the jail is gone. The deny protects the inode it was mounted on, not the path the host reads. Found by an embedder's swap onto brig (four strict-xfail tests there plant it: a directory on the way to the interpreter, to a git config, to a layer file).
<!-- SECTION:DESCRIPTION:END -->
