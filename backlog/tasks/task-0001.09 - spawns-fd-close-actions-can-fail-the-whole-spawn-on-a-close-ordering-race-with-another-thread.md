## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
infra/processes.py's `spawn` (TASK-0001.05 AC#1) enumerates this process's open, inheritable fds and builds one `os.POSIX_SPAWN_CLOSE` file action per fd outside the plan's allow-list. Measured on this machine: if a close action names a fd that is no longer open by the time the OS performs it (`EBADF` -- confirmed empirically, not theoretical), `os.posix_spawn` fails the *entire* spawn, not just that one action, the same way a bad `argv[0]` does.

The scan runs in this process before the spawn; the spawn itself (fork+exec in the C library) happens after. In a multi-threaded embedder, another thread closing one of those fds in that window turns a would-have-succeeded spawn into a `JailSpawnFailed`, raised for a reason that has nothing to do with `argv` or the sandbox policy. `spawn`'s own docstring already reasons carefully about multi-threaded embedders for the fork-safety choice (`posix_spawnp` over hand-rolled fork/exec); this is the same category of hazard, left open this time.

Narrowing it needs a design choice outside TASK-0001.05's scope: confirm each fd is still open immediately before the call (still racy, just a smaller window), retry once on `EBADF` and rebuild the close actions, or something else. File this to carry that choice; TASK-0001.05 only needed `spawn` to close what the plan does not allow, which it does.
<!-- SECTION:DESCRIPTION:END -->

## Review (close-work, TASK-0001.09)

The implementing agent left no notes of its own, yet both `spawn`'s docstring (`src/brig/infra/processes.py:238`) and `tests/e2e/test_spawn_close_action_race.py`'s module docstring cite "this task's implementation notes" for the measured counts that are AC#2's whole anti-vacuity argument. The reviewer re-measured those counts independently rather than close on a reference to nothing; they are recorded here so both docstrings are true.

Differential, this host (darwin, Python 3.15.0rc2), racing the same planted inheritable pipe fd with the same real second thread, the same lowered `sys.setswitchinterval(1e-5)`, and the same `_RACE_FRACTIONS` x 8 iterations the battery itself uses, measured baseline spawn 0.0034s:

- Without the retry (calling `_spawn_leading_a_new_group` + `_close_actions` directly, i.e. the pre-fix path, no production code changed): **31/32 spawns failed with EBADF**.
- With the retry, through `spawn` as shipped: **0/32 failed**, every child exited 0.

So the race is genuinely plantable here and the battery's passing assertion is not vacuous. `tests/e2e/test_spawn_close_action_race.py` passes on this host (not skipped: no `/proc/self/fd`).

AC#1's "design decision" lives in `spawn`'s docstring, not in a `backlog/decisions/` file -- no decision file mentions `posix_spawn` or EBADF, and this task carries no `type: design` or `references` key, so the docstring is the home. It states the choice (retry once, on EBADF only, rebuilding the close actions from a fresh scan), why the retry is likelier-but-not-guaranteed correct, why a second EBADF is not retried, and why confirm-before-close was rejected (narrows the same window at double the scan cost on every spawn).

The orchestrator's two post-implementation fixes were sanity-checked and touch nothing in the race: the `-> int | ProcessUnknown` annotation is `reap`'s honest return type, and the `[tool.pypeeker.import-time-side-effects] allow = ["os.path.isdir"]` gate entry covers one bare stdlib call in the `skipif` decorator, matching the `shutil.which(...) is None` pattern used elsewhere in this suite.

Findings reported, none filed:
- CI is `ubuntu-latest`, where `/proc/self/fd` exists and this battery skips, so AC#2's test never runs in CI and a regression in the retry would be caught on no machine but a macOS dev host. Honest per decision-0001's "report not run rather than pass vacuously" rule and not an unmet criterion, but it leaves the retry's only test outside the gate. Belongs with whatever owns platform-divergent e2e coverage.
- That `allow = ["os.path.isdir"]` is repo-wide: unlike the `over-exposed-module-symbol` entry just below it, which is scoped to the three test-layer prefixes, this one would also permit an import-time `os.path.isdir` inside `src/brig`. Cosmetic today (one call site), worth scoping if the rule supports an `include`.
- The module docstring's second bullet (lines 39-47) is over-indented relative to its own first line, and its Linux counts (60/60) are not reproducible from this host.
