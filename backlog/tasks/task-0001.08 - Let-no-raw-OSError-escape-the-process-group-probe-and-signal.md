## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Why

`infra/processes.py`'s `group_alive` probes a process group with `os.killpg(pgid, 0)`
and converts only `ProcessLookupError` (ESRCH) into an answer. On this host (macOS,
Darwin 27) that probe intermittently raises `PermissionError` (EPERM) instead, which
nothing catches: it travels up through `drivers/bwrap.py`'s `Verify` case and out of
`destroy_jail` as a raw stdlib exception. Decision-0001 rule 13 and `presentation/
errors.py`'s own docstring say an embedder handles brig's own error types and never
an infra one, so this is a hole in that promise.

Measured against the current code, through brig's public API, no bwrap required:

```python
import os, signal, time, collections
from brig import Jail, destroy_jail
from brig.domain.effects import Process
from brig.infra.processes import spawn
from brig.presentation.errors import JailTeardownFailed

counts = collections.Counter()
for _ in range(25):
    p = spawn(("/bin/sh", "-c", "trap '' TERM; sleep 30 & exit 0"))
    time.sleep(0.05)
    try:
        destroy_jail(Jail(process=Process(pid=p.pid, pgid=p.pgid)))
        counts["clean"] += 1
    except JailTeardownFailed:
        counts["JailTeardownFailed"] += 1
    except Exception as exc:
        counts[type(exc).__name__] += 1
    try:
        os.killpg(p.pgid, signal.SIGKILL)
    except OSError:
        pass
print(dict(counts))
```

Result: `{'JailTeardownFailed': 23, 'PermissionError': 2}` -- roughly 2 in 25, and
reproduced again at 2 in 60 in a second run. The `JailTeardownFailed` majority is the
separate, already-tracked TASK-0001.07 timing problem; the `PermissionError` is this
one.

## Root cause

At the moment EPERM fires, `ps -o pid,pgid,ppid,uid,stat,comm -g <pgid>` lists no
process at all, and the pgid is still the leader's own pid, spawned by this process
moments earlier -- so this is not pgid reuse by a foreign process. What remains in the
group is a zombie: the group member that outlived the leader was reparented to pid 1
when the leader exited, and between its death and pid 1 reaping it, Darwin's permission
check on a signal to that zombie answers EPERM rather than the ESRCH a fully vanished
group gives. The group is, for every purpose brig cares about, gone.

`signal_group` has the same unguarded shape (`os.killpg(pgid, sig)` with only its
docstring's `ProcessLookupError` considered), so the TERM and KILL rungs can leak the
same exception on the same window.

## Scope

Out of scope for TASK-0001.06, which closed the spawn and wait hazards: EPERM out of
`group_alive` is a group-liveness probe, not a fork and not a wait on a child, so it
is neither clause of that task's AC#1. Filed here instead, per that task's own
instruction to park out-of-scope discoveries on the parent intent.

Distinct from TASK-0001.07: that one is a correctly-typed `JailTeardownFailed` raised
too early (a false negative with the right error type); this one is a raw non-brig
exception escaping at all.

Added .claude/rules/driver-exception-boundary.md as a standing reminder. Worth considering, within this task's own scope, whether the pattern is mechanizable as a pypeeker rule (flag a driver's bare/missing except around an infra. call) rather than relying on a reminder alone -- not attempted here, just named.

Fixed in `src/brig/infra/processes.py`: `group_alive` now catches `OSError` broadly (was `ProcessLookupError` only) and answers `False`; `signal_group` now wraps its `os.killpg` call in `try/except OSError: pass` (was unguarded). Both docstrings updated with the EPERM root cause and why the catch is broad rather than naming errnos. No change was needed in `presentation/drivers/bwrap.py`: once infra never raises for these two calls, the driver's existing unwrapped `SignalGroup`/`Verify` match-arms have nothing left to leak.

AC#3's e2e gateway test added to `tests/e2e/test_processes_gateway.py` (`test_destroy_jail_survives_the_leader_exiting_before_its_group`): drives the leader-exits-before-its-group shape through `destroy_jail` itself (brig's public API) for 150 iterations, recording any exception type that is not `JailTeardownFailed`. It imports `brig`'s public API plus `brig.infra.processes` only (decision-0001 rule 4); `Jail.process` (typed to `brig.domain.effects.Process`, which an e2e test may not import) is filled with the real `SpawnedProcess` from this test's own `spawn` call via `cast(Any, ...)`, since every downstream reader only touches `.pid`/`.pgid`, which `SpawnedProcess` already has.
