## Description

## Why

An adversarial review of the walking skeleton (TASK-0001.03) found two confinement holes that
decision-0001's order, step 4 does not name (it names the filesystem policy, the environment,
channels and the teardown ladder, not these):

- infra/processes.py spawns with a hand-rolled fork/exec that closes no file descriptor, so every
  non-CLOEXEC fd the embedder holds open is inherited straight into the jail. An inherited fd
  bypasses the mount namespace entirely: the jailed process reads and writes through it whatever
  the filesystem policy says. (subprocess closes fds by default; this path does not.)
- The compiled argv carries no --new-session. bwrap's own documentation calls --new-session
  strongly recommended, because without it the sandbox can escape through the TIOCSTI ioctl on a
  shared controlling terminal. Today this is blocked only incidentally, by the os.setsid() that
  infra/processes.py's child happens to call before exec -- not by the jail's own flags, and not by
  anything that would notice if that setsid moved.

Both are policy for a jail type to state and a battery to grade (rule 11), not fixes to the
walking skeleton.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria

- [x] #1 A jail type states which file descriptors its process may inherit, and the spawn path closes every other one

- [x] #3 Each hole has an e2e battery that plants the violation with a positive control (rule 11): an fd passed in is unreadable in the jail, and TIOCSTI injection fails
