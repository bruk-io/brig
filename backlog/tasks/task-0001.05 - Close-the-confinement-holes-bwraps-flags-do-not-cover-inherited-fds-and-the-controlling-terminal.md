## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Why

An adversarial review of the walking skeleton (TASK-0001.03) found two confinement holes that
decision-0001's order, step 4 does not name (it names the filesystem policy, the environment,
channels and the teardown ladder, not these):

- infra/processes.py spawns with a hand-rolled fork/exec that closes no file descriptor, so every
  non-CLOEXEC fd the embedder holds open is inherited straight into the jail. An inherited fd
  bypasses the mount namespace entirely: the jailed process reads and writes through it whatever
  the filesystem policy says. (subprocess closes fds by default; this path does not.)
- The compiled argv carries no --new-session. bwrap's own documentation calls --new-session
  strongly recommended, because without it the sandbox can escape through the TIOCSTI ioctl on a
  shared controlling terminal. Today this is blocked only incidentally, by the os.setsid() that
  infra/processes.py's child happens to call before exec -- not by the jail's own flags, and not by
  anything that would notice if that setsid moved.

Both are policy for a jail type to state and a battery to grade (rule 11), not fixes to the
walking skeleton.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A jail type states which file descriptors its process may inherit, and the spawn path closes every other one
- [x] #2 The bwrap jail type passes --new-session, so the TIOCSTI escape is closed by the jail and not by infra's setsid
- [x] #3 Each hole has an e2e battery that plants the violation with a positive control (rule 11): an fd passed in is unreadable in the jail, and TIOCSTI injection fails
<!-- AC:END -->

## AC#2's "unattributable" finding is superseded on the real target platform (from TASK-0001.12's review)

Appended by TASK-0001.12's reviewer. **No criterion was ticked or reworded here, and this task stays open** -- this only records that the ground AC#2's blocker stood on has moved, so whoever picks this up next does not re-derive it.

This task's earlier review recorded as measured fact that infra's unconditional `setsid=True` always runs first, so `--new-session` can never be credited and "no black-box battery can attribute the closure". That holds **only on macOS**. TASK-0001.12 found `setsid=True` is compiled out of uv's managed CPython -- the build `.github/workflows/ci.yml` uses -- so on this project's own CI platform `SpawnedProcess.session_detached` is `False`, infra detaches no session, and the attribution is gradable.

I re-ran the three-row differential myself (not reading TASK-0001.12's notes, whose own script was not checked in), on `ubuntu:24.04` x86_64 under uv-managed CPython 3.15, `dev.tty.legacy_tiocsti = 1`, each row driving brig's real `spawn` inside a `pty.fork()` session and asserting `session_detached is False` first:

| case | result |
| --- | --- |
| positive control, no jail, owns the pty | exit 0 -- **INJECTED, hole open** |
| `_BWRAP_ARGV` as `compile_run` produces it (with `--new-session`) | exit 101 -- **denied, EPERM** |
| the same argv with only `--new-session` removed | exit 0 -- **INJECTED, hole open** |

`--unshare-all` and `--die-with-parent` are present in both bwrap rows, so the third row is a genuine negative control: `--new-session` is the **sole** closer of the TIOCSTI hole there. AC#2's claim -- closed by the jail "and not by infra's setsid" -- is therefore true on the platform that matters, and demonstrable.

**What AC#2 still needs, and why this task is not done.** The evidence above is ad hoc: a script run twice by two agents and checked in neither. Nothing in `tests/` grades it. `test_tiocsti_injection_fails_in_a_real_bwrap_jail` asserts the hole is closed without saying by which layer, and the gateway test now *skips* wherever the attribution is gradable. So the differential battery has to be written into the real test suite -- and it needs an argv `domain/jail_types/bwrap.py`'s `compile_run` deliberately does not produce, which is the test-design question TASK-0001.11 owns. Note also that such a battery can only run where `session_detached` is `False`, so it must report itself not run on macOS rather than pass there.

Secondary, for whoever closes this: the earlier review's caveat that "the in-jail halves have never executed anywhere" is no longer true -- the full suite now runs green on real Linux x86_64 with bwrap installed (38 passed, 1 skipped), including both bwrap TIOCSTI and fd-inheritance batteries. CI itself still has never run, as the repo has no remote.
