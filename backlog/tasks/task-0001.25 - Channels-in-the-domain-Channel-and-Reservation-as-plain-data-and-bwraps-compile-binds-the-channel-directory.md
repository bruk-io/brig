## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
decision-0002 item 2's domain half: domain/channels.py holds Channel and Reservation (name, bound_path, endpoint) as frozen data, pure. A reservation is made before the process starts, so the caller learns each endpoint before create and puts it in the command's argv itself (old SPEC decision-184/186: argv, never env, so nothing that scrubs the environment can lose it). bwrap's compile binds the per-jail channel directory into the jail at the endpoint's directory.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 domain/channels.py defines Channel and Reservation as frozen data and a pure function that derives each reservation's endpoint (the in-jail path) and bound_path (the host path) from a channel name and the per-jail channel directory; a unit test pins it deterministic and refuses a name that would escape the directory
- [ ] #2 bwrap's compile adds a writable bind of the per-jail channel directory when the plan declares channels, and none when it declares none; unit tests pin both
- [ ] #3 A reservation reaches the jailed command only through argv: the public API returns each endpoint before the process starts, and an integration test fails if a reservation's endpoint or bound_path appears in the env StartSupervisedCommand carries
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
### Decisions this plan takes (with why)

1. **Domain shape** (`src/brig/domain/channels.py`, new, pure): `Channel(name)` -- a declared channel; `ChannelDirectory(host_path, jail_path)` -- the per-jail channel directory as seen from each side of the boundary; `Reservation(name, bound_path, endpoint)`; `Reservations(directory, reservations)` -- what a reserve hands back and what compile reads; `ChannelRefused(name)` -- the refusal value. `reserve(channels, directory) -> Reservations | ChannelRefused` derives `bound_path = host_path/name` and `endpoint = jail_path/name` by string join (rule 2: no `os.path`), and refuses a name that is empty, `.`, `..`, contains `/` or NUL (each would escape or alias the directory), or repeats an earlier name. A refusal is a value (rule 9: only `api` raises), matched in `api` and raised there as `ChannelNameRefused` from `presentation/errors.py` (rule 13).
2. **Two directory fields, not one.** bwrap binds the directory at its own host path (the only placement reachable under `WHOLE_HOST_READ_ONLY`; TASK-0001.22 measured a fixed in-jail path EROFSing on the read-only host root), so in practice `host_path == jail_path` today. The derivation still takes both, so the unit test can feed two different strings and tell `endpoint` from `bound_path` -- with one directory the two fields are byte-identical and a swap would pass.
3. **Where the bind lands**: a new keyword `channels: Reservations | None = None` on `compile_supervisor_launch`, not on `compile_run`/`Plan` -- the same reasoning TASK-0001.16 recorded for `FsPolicy` (compile_run builds no bwrap argv; a field there reaches no flag). Emits `--bind host_path jail_path` only when `channels` declares at least one reservation; placed after the unconditional `state_dir` ro-bind (the channel directory lives beneath the state directory, and bwrap applies binds in argv order, later wins) and before the virtual-fs flags. Default emits nothing, so the existing byte-exact argv tests and `tests/e2e/test_tiocsti_battery.py`'s mirrored prefix stay unchanged.
4. **How the public API hands endpoints back before the process starts**: a new public `reserve_channels(channels, *, directories=...) -> Reservations` in `presentation/api.py`, called before `create_bwrap_jail`; the caller reads each `Reservation.endpoint`, writes it into `command` itself, then passes the same `Reservations` to `create_bwrap_jail(..., channels=...)`, which threads it into `_supervisors_for` -> `compile_supervisor_launch`. Nothing puts a reservation into `env` (old SPEC decision-184/186: argv, never env). The per-jail directory's path comes from a small port, `ChannelDirectoryPort.allocate() -> str` in `presentation/ports.py`; its default names `<state_dir>/channels/<random token>` and creates nothing -- creating, privatising and removing that directory, and the reachability guard, are TASK-0001.26's (infra/sockets.py). The port keeps the integration test off the real filesystem (a fake in `tests/integration/fakes.py`) and is the seam .26 grows.

### Order of work

1. `domain/channels.py` + `tests/unit/test_channels.py` (derivation deterministic and discriminating; each escaping name refused; duplicate refused; no channels -> empty reservations).
2. `compile_supervisor_launch`'s `channels` parameter + two unit tests in `tests/unit/test_bwrap_compile.py` (bind present at the exact position when channels are declared; argv identical to the no-channels call when none are).
3. `ChannelDirectoryPort` in `ports.py`; `ChannelNameRefused` in `errors.py`; `reserve_channels` and the `channels` parameter on `create_bwrap_jail` in `api.py`; re-exports in `src/brig/__init__.py`.
4. `FakeChannelDirectories` in `tests/integration/fakes.py`; `tests/integration/test_channel_reservations.py`: endpoint known before create, appears in the argv `FakeSupervisors.start` recorded, and neither endpoint nor bound_path appears in its recorded env (keys or values), even with a permissive `EnvPolicy` and a host-like env; a refused name raises `ChannelNameRefused` before anything starts.
5. `docs/glossary.md`: **channel**, **reservation**.
6. `just check` throughout; `uv run just done` at the end, recorded with record-check (full).

### Risks

- **A real jail declaring channels does not work until TASK-0001.26**: the bind's host directory does not exist yet, and bwrap creating its mountpoint under the read-only state-dir bind EROFSes (TASK-0001.22's measured shape). This slice proves argv shape and the argv-not-env contract only; no e2e here. Stated in the notes so nobody reads it as shipped end to end.
- Pypeeker strict rules on new public names (`over-exposed-module-symbol`, `brig-class-forms`, `barrel-only`): mitigated by re-exporting from `brig/__init__.py` and using only frozen dataclasses and a Protocol.
- AF_UNIX `sun_path` length (~108 bytes Linux, 104 macOS) is not checked here; a long state dir could make an endpoint unbindable. Out of scope; noted as a follow-up candidate for .26/.27.
- `docs` (`mkdocs --strict`) renders `::: brig`; new docstrings must be valid Google style.

What changed
- src/brig/domain/channels.py (new, pure): Channel(name), ChannelDirectory(host_path, jail_path), Reservation(name, bound_path, endpoint), Reservations(directory, reservations), ChannelRefused(name), and reserve(channels, directory) -> Reservations | ChannelRefused. bound_path = host_path/name, endpoint = jail_path/name (string join, no os.path). Refuses empty, ".", "..", a name containing "/" or NUL, and a repeated name, as a value (rule 9).
- src/brig/domain/jail_types/bwrap.py: compile_supervisor_launch gains `channels: Reservations | None = None`; when it declares at least one reservation it emits `--bind <host_path> <jail_path>` right after the state_dir ro-bind (the channel dir lives beneath the state dir; later bind wins) and before the virtual-fs flags. None/empty emits nothing, so the existing byte-exact argv tests and the e2e tiocsti prefix copy are untouched.
- src/brig/presentation/ports.py: ChannelDirectoryPort (allocate() -> str). errors.py: ChannelNameRefused. api.py: reserve_channels(channels, *, directories=...) -> Reservations, `channels=` on create_bwrap_jail threaded through _supervisors_for into compile_supervisor_launch. brig/__init__.py re-exports Channel, ChannelDirectory, ChannelDirectoryPort, ChannelNameRefused, Reservation, Reservations, reserve_channels.
- tests: tests/unit/test_channels.py (AC#1), two new tests in tests/unit/test_bwrap_compile.py (AC#2), tests/integration/test_channel_reservations.py + FakeChannelDirectories in fakes.py (AC#3). docs/glossary.md: channel, reservation.

Decisions
- Endpoint layout: the per-jail channel directory is `<state_dir>/channels/<secrets.token_hex(8)>`, bound at its own host path, so for bwrap endpoint == bound_path. A fixed in-jail path (e.g. /run/brig) was rejected: its mountpoint would have to be created on WHOLE_HOST_READ_ONLY's read-only root, the EROFS TASK-0001.22 measured. ChannelDirectory still carries both sides so the unit test feeds two different strings and a swapped derivation fails.
- How endpoints come back before the process starts: a separate public call, reserve_channels, made before create_bwrap_jail. The caller reads Reservation.endpoint, writes it into `command` itself, then passes the same Reservations to create_bwrap_jail(channels=...). Nothing in brig writes a reservation into env.
- The bind lives on compile_supervisor_launch, not Plan/compile_run (same reasoning TASK-0001.16 recorded for FsPolicy: compile_run builds no bwrap argv). AC#2's "the plan declares channels" is read as "the compile is given a non-empty Reservations".
- ChannelDirectoryPort was added (not named in the plan's file list at first draft, but in the final plan): it keeps the integration test off the real filesystem and is the seam TASK-0001.26 grows (create/privatise/remove).

Known gaps, stated honestly
- A real bwrap jail that declares channels does NOT work yet: the default port names the directory but creates nothing, so bwrap would try to mkdir the mountpoint under the read-only state-dir bind and fail (EROFS -> JailExitUnknown). Creating it is TASK-0001.26's AC#1. No e2e test in this slice for that reason.
- reserve_channels allocates before validating names; harmless now (allocate creates nothing), but once TASK-0001.26 makes allocate create the directory, a refused name would leak it -- .26 should validate first or remove on refusal.
- AF_UNIX sun_path length (~108 bytes Linux, 104 macOS) is not checked; a long BRIG_HOME can make an endpoint unbindable. Candidate for .26/.27.
- Jail does not carry its Reservations yet; .26 (removal on destroy) and .27 (readiness) will need it.

Nothing outside the plan's files was changed. `uv run just done` passed (record above); e2e skips are the pre-existing bwrap-not-present skips on this macOS host.
