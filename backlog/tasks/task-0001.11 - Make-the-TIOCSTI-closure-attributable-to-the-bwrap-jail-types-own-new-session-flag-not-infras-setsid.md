## Why (superseded premise, corrected)

This task's original premise -- that infra's unconditional `setsid=True` always detaches a
session before bwrap's own argv is parsed, so `--new-session` can never be independently
credited -- was measured only on macOS and is **false on this project's own CI toolchain**.
TASK-0001.12 found that `uv`'s managed CPython on real Linux cannot satisfy `setsid=True` at all
(a permanent toolchain limitation, not a bug) and falls back to `setpgroup=0`, which does **not**
detach a session. On that platform, `--new-session` is the *only* thing closing the TIOCSTI hole.

TASK-0001.12's own investigation (and TASK-0001.12's independent closing reviewer, separately)
ran the differential control this task originally asked for: the same bwrap argv, with and
without `--new-session`, on real Linux x86_64 with `session_detached=False`. Positive control
(no jail) injects; brig's real argv (with `--new-session`) is denied; the same argv with
`--new-session` removed injects again. That is a genuine negative control -- `--unshare-all` and
`--die-with-parent` are present in all three bwrap rows and do not close the hole -- so the
attribution this task asked for already holds for real, on the platform that matters. It was not
checked into the test suite; it exists only as prose on TASK-0001.05 and TASK-0001.12's own notes.

## What this task actually is now

Not "design a new architectural seam" (the original framing) -- that seam already exists via
`session_detached`. Write the already-proven differential into `tests/e2e/test_tiocsti_battery.py`
as a real, repeatable test, guarded so it only runs where it can mean something
(`session_detached=False` -- the real Linux CI toolchain; it has nothing to prove where infra
already detaches a session, same as the existing gateway test's skip).
