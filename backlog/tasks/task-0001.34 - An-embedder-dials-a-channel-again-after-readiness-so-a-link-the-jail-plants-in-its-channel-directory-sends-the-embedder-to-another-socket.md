## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
await_channel_ready makes a verified connect (decision-0005: the peer listens inside the jail's PID namespace), then closes it and returns ChannelReady carrying nothing. The embedder then dials the reservation's host path itself with a plain connect, which follows a symlink. The jail can write its channel directory, so once readiness has passed it can replace its socket with a link to any socket the embedder's user can reach on the host (an agent socket, a container daemon), and the embedder connects there and speaks its protocol to it. The old brig refused a link in the channel directory on every connect. Found by an embedder's review of its channel owners.
<!-- SECTION:DESCRIPTION:END -->

## Worker's report

**What changed.** `ChannelReady` now carries the verified, connected socket, so an embedder never dials a reservation's `bound_path` again.

- `infra/sockets.py`: `ChannelReady` gains `connection: socket.socket`. `channel_ready` runs the connect and the check in a private `_verify` (returning a private `_Verified`, `ChannelNotReady` or `ChannelRefused`). The ready path returns the socket open. Every other path closes it before returning: a failed connect, each refusal, and the one raise (`OSError` for a `jail_namespace_fd` that is not open, closed through `except BaseException: close; raise`).
- `presentation/ports.py`: the public `ChannelReady` gains `connection: socket.socket`. Its docstring says the embedder uses it, owns it and closes it (`with ready.connection:`), never dials `bound_path`, and needs a second `await_channel_ready` for a second connection. The socket is blocking with no timeout and non-inheritable (Python's default, PEP 446). The `ChannelReadinessPort.ready` docstring says the same.
- `presentation/jail.py`: the real wiring passes `outcome.connection` through. `presentation/api.py`: `await_channel_ready`'s docstring says so. The loop itself needed no change. Infra closes a not-ready or refused attempt's socket, and the loop returns at the first `ChannelReady`, so only the attempt that returns keeps its socket. `ChannelJailFinished` and the timeout's `ChannelNotReady` hold none.
- Docs: `docs/spec/index.md` (the infra bullet, and a paragraph in Presentation on how an embedder uses a channel, with what holds it), `docs/glossary.md` (a new `readiness` entry, and `reservation` says the path is never dialled), `README.md` (one paragraph), and `domain/channels.py`'s `Reservation` docstring.
- Tests:
  - The e2e repro, in `tests/e2e/test_channel_readiness_battery.py`, runs in real bwrap. The jail's listener answers the readiness connect, then unlinks its socket and symlinks the path to a host listener. The test now asserts that `outcome.connection` answers `jail` and that a fresh plain dial answers `host`; the second assertion is the control that the swap happened.
  - Integration: `FakeChannelReadiness` takes the class `ChannelReady` in its script for an attempt that connects. It hands out one end of a `socket.socketpair()` and keeps the other in `peers`. The channel e2e tests pass with `-W error::ResourceWarning`.

**Shape, against decision-0001 rules 5 and 7 and `brig-class-forms`.** I kept a frozen dataclass with a `socket.socket` field.
- Rule 7 (four uses of `class`): a frozen dataclass is for shape, and a class that holds changing state belongs only in `infra/`. `ChannelReady`'s own fields never change. It holds a reference, and the state behind that reference is the stdlib socket's, not the class's. The gate's checks are `frozen=True`, no `self.<name> =` and no disallowed base, and it passes them.
- The alternative was a stateful owner class with `close`/`__enter__`. Rule 7 would put it in `infra/`, and an infra type may not cross a port (ports.py's own rule). The stdlib socket is already the owner and already a context manager.
- Rule 5 (fakes, never patches): testing it needs no patch. The fake hands out a real in-process `socketpair` end, and the test asserts on its state (the bytes through it), not on calls. No host fact enters this way.
- Rule 8 (data says what it is) does not bind it: `ChannelReady` is neither persisted nor sent.
- Equality is now by socket identity, so the tests' `== ChannelReady()` became `isinstance` checks.
