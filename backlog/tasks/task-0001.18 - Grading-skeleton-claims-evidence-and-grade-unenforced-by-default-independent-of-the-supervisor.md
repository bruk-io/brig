## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
domain/claims.py: `Claim` (frozen dataclass: name, description).

domain/grades.py: `Grade` StrEnum (ENFORCED/VIOLATED/UNENFORCED) and `Evidence`
(frozen dataclass: `control_observed`, `violation_blocked` -- two fields, not one,
because rule 11 asks for "a battery that plants the violation WITH a positive
control": `violation_blocked=True` alone can't prove the probe could detect
anything, so `grade()` only reads it once `control_observed` confirms the control
was actually seen getting through). `grade(claims, evidence)` is pure; no evidence
key, or a key whose control was never observed, grades UNENFORCED.

presentation/report.py: `render(report) -> str`, one line per claim.

Public API (src/brig/__init__.py): exported `Claim`/`Evidence`/`Grade`/`grade`
straight from domain, and `render` from presentation. Required because
pypeeker's `brig-test-layers` rule (decision-0001 rule 4) only lets tests/e2e and
tests/integration import brig's public API or one infra module -- never
brig.domain/brig.presentation directly -- so the e2e wiring test below could not
otherwise call `grade()` at all. Deviates from the layout's literal "__init__.py
re-exports presentation's api": grading's four names are pure data/a pure function
with no infra behind them, so routing them through presentation first would be an
import with no job. Verified empirically (not just reasoned) that this passes
`brig-layers`: `just gates` is clean. Noted in `__init__.py`'s own docstring.

Wiring the two existing batteries (AC#3): NOT by shelling out to pytest and
reading the battery file's exit code -- confirmed with a second opinion before
building this that pytest reports a file where every test skips as a pass (exit
0), and both battery files legitimately skip on this host (no bwrap on macOS;
TIOCSTI's gateway also needs a setsid flag this interpreter may lack), so that
approach would have fed a fabricated "blocked" into grade() for claims nothing
measured -- the exact dishonesty rule 11 rules out. Instead,
tests/e2e/test_claims_wiring.py measures each claim in-process, itself, the same
way the battery it wires in does:
- `fd_inheritance`: reimplements the gateway probe (plant a pipe fd inheritable,
  spawn through `brig.infra.processes.spawn` with/without it on the allow-list,
  read back what the spawned probe saw) against the real `spawn` -- no bwrap
  needed. Ran for real on this host: grades ENFORCED from real evidence.
- `tiocsti_closure`: measures against a real bwrap jail (`create_bwrap_jail`/
  `run_jail` through the public API), with its own positive control via a fresh
  pty (`pty.fork()`, mirroring test_tiocsti_battery.py's own technique). Where
  bwrap isn't installed (this host, macOS) it returns no evidence at all rather
  than a skip, so `grade()` reports UNENFORCED -- an honest result, not a gap:
  verified that branch runs and asserts correctly on this host. The
  bwrap-measuring branch is unverified here (no bwrap on macOS) and will run for
  real in CI on Linux, same as the two battery files it wires in.

Did not import or alias the battery files' own private helpers (`_run_fd_probe`,
`_run_in_pty_session`, etc.) -- pypeeker's under-exposed-access rule forbids
reaching into another module's `_names`, and the task's hard constraints named no
reason to edit test_fd_inheritance_battery.py/test_tiocsti_battery.py to expose
them, so the wiring test's probes are a condensed, independent reimplementation of
the same measurement instead. Those two files were not modified.

## Review (independent, did not do the work): NOT CLOSED

Blocking, AC#3. `tests/e2e/test_claims_wiring.py:_measure_tiocsti_closure` computes
`violation_blocked=violation_exit != 0` from `run_jail`'s raw exit code. Every
non-zero exit that is not a denial grades the claim ENFORCED from nothing: bwrap's
own setup failure (user namespaces disabled -- ordinary in CI) exits 1; a probe
crash inside `_run_in_pty` exits 99 via `except BaseException`; `create_bwrap_jail`
raising `JailSpawnFailed` takes the same 99 path. That is the exact fabrication this
file's module docstring says it exists to prevent, on the one branch (bwrap present)
that has never executed anywhere.

Two in-repo standards show this is a defect, not a judgement call:
- The battery being wired in, `tests/e2e/test_tiocsti_battery.py`, already solved it:
  `_ERRNO_EXIT_OFFSET + errno` as a denial protocol, with its own comment that this
  keeps a denial from colliding with 1/2/126/127, plus `_PROBE_CRASHED_EXIT_CODE`.
  The condensed reimplementation dropped that protocol.
- `_measure_fd_inheritance` in the same new file requires the exact bytes
  `b"CLOSED:9"` -- it refuses to read "not the success string" as "blocked". The
  TIOCSTI measurement uses `!= 0`. Same file, two standards; the loose one is the
  unverified one.

Fix shape: denial must be a positive signal (the battery's errno-offset protocol, or
a known byte on a report fd); anything outside the known range is
`control_observed=False`/no evidence, never `violation_blocked=True`.

Met: AC#1 (domain/claims.py, domain/grades.py, no-evidence -> UNENFORCED, checked
against decision-0001 rule 11's own text -- the two-field Evidence is consistent with
rule 11's "plants the violation with a positive control", not a widening of the
finish line). AC#2 (presentation/report.py `render`). AC#3 not met for the reason above;
its fd_inheritance half is genuinely measured and sound.
