2. jail_types/bwrap.py's compile_run takes a policy param, translates binds into --ro-bind/

   per-embedder policy API is out of scope here, just the mechanism).

   (skip-guarded on this host), with a positive control (the same path IS reachable with no
   policy, i.e. today's placeholder behavior), per rule 11.

  walking-skeleton e2e test if it is not also updated to pass an explicit (or default) policy.

  shows the violation when planted.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
finish-moved (AC#2): the task's committed plan named `compile_run` as the function that takes the policy and translates its binds into bwrap's own `--ro-bind`/`--bind` flags. By the time this task started, TASK-0001.15 step 4 had already landed and changed that: `compile_run` builds no bwrap argv at all any more -- it only names the real command the jail's supervisor runs as its own child (`Plan`'s own docstring already records this as the reason `Plan.inheritable_fds` has no current reader). The single hardcoded `--ro-bind / /` placeholder AC#2's own text points at lives in `compile_supervisor_launch` now (`_BWRAP_ARGV`, before this task), which is what actually builds the supervisor's own bwrap-wrapped launch line. A `policy` parameter on `compile_run` would reach no flag at all -- the exact ambiguity this project's own rule 11 exists to rule out, not a mechanism. Landed the parameter on `compile_supervisor_launch` instead, confirmed against the real architecture rather than argued from the stale AC text, and updated AC#2's wording here to match (finish-moved label added).

Design for threading `policy` through `presentation/api.py` (AC#2/#3): `create_bwrap_jail` gained `policy: FsPolicy = WHOLE_HOST_READ_ONLY`. The supervisor's own launch line (`compile_supervisor_launch`'s output) depends on `policy`, and `infra.supervisor.link.LiveSupervisors` fixes its own launch argv for its whole lifetime (TASK-0001.15's own design) and has to be the *same* instance across a jail's create/start/destroy calls (it owns that jail's still-open events pipe). So a jail created with a non-default `policy` now gets its own dedicated `LiveSupervisors` instance (`_supervisors_for`, built fresh, cheap -- no I/O until `start` is called), carried on a new `Jail.supervisors` field; `run_jail`/`destroy_jail` default to `jail.supervisors` instead of the module's one shared instance when their own caller passes no explicit `supervisors=`. The default policy's jail still goes through the one shared module-level instance unchanged (`_supervisors_for` returns it when `policy == WHOLE_HOST_READ_ONLY`), so nothing about the zero-argument calling convention every existing test and this task's own battery use (`create_bwrap_jail(cmd)`, `run_jail(jail)`, `destroy_jail(jail)`) changed for the default path. `Jail.supervisors` defaults to that same shared instance too, so `tests/e2e/test_processes_gateway.py`'s direct `Jail(process=...)` construction (no `supervisors=`) is unaffected.

AC#3's battery (tests/e2e/test_fs_policy_battery.py): plants a secret file under a fresh directory of its own beneath /tmp, then runs the same read probe (exit code only -- DRAFT-0010: the supervised command's own stdout is the supervisor's wire pipe now, so a probe can never report through a pipe) through create_bwrap_jail/run_jail/destroy_jail twice -- once under a policy that mirrors WHOLE_HOST_READ_ONLY's own practical coverage (every top-level host directory, read-only, minus virtual filesystems the probe does not need) except /tmp, and once under WHOLE_HOST_READ_ONLY itself as the positive control. Violation: exit code 2 (ENOENT -- the path does not exist in the jail's own mount namespace, not merely permission-denied, matching the allow-list policy model). Positive control: exit code 0 (the same path, same probe, reachable). The narrowed policy mirrors rather than hand-picks paths, specifically so the supervisor's own interpreter and this repository (wherever either actually live under / on the host running it) stay reachable without this test reaching past the public API to ask (rule 4) -- measured for real in a --privileged ubuntu:24.04 container: the mirror policy resolved to 17 top-level binds there, genuinely covering /repo (program.py and the venv) and /root (the uv-managed interpreter's real target) while withholding /tmp, confirmed by printing the resolved FsPolicy and both paths' realpath.

Proof: just lint/just typecheck/just gates all clean on macOS both before (baseline) and after this change. just done green in full on macOS (lint, typecheck, gates, pypeeker rule tests, unit x14->15, integration x5 twice, e2e x15->17 passed/9 skipped, docs build, arch-validate, arch-lint) -- nothing that passed before regressed; the two new unit/e2e tests this task added are the only count change. Real Linux + real bwrap, docker run --privileged ubuntu:24.04 (repo copied in, uv sync, ruff installed as a uv tool per TASK-0001.20's own already-filed gap): just typecheck and pypeeker check --strict clean; uv run just lint clean; pytest tests/ pypeeker_rules/tests -rs -> 63 passed, 3 skipped (all pre-existing, measured reasons, same set task-0001.15 already recorded minus nothing new). The new battery's own two tests passed for real against real bwrap in that container, individually confirmed with -v.

Jail.supervisors is a genuine shape change to Jail (decision-0001's own docstring on Jail said a jail type with more to it is a later slice's addition here, not the walking skeleton's -- this is that later slice). Not filed separately: it is squarely what AC#2's own 'thread the policy through api.py' asked for once the per-jail-varying-launch-line constraint was traced through, not an unrelated discovery.
