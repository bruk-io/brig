## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
### Order of work

1. Add `tag paused` to docs/architecture/shared/_spec.c4, alongside the existing `external`,
   `deprecated`, `planned` -- oci is explicitly deferred indefinitely (decision-0001: "paused"),
   a different claim than "planned next" (Seatbelt, the supervisor), so it earns its own tag
   rather than overloading `#planned`.
2. Model Seatbelt's slice: `domain/jail_types/seatbelt` and `presentation/drivers/seatbelt`
   components under brig.library, tagged `#planned`, same pattern as the supervisor container.
3. Model oci's slice: `domain/jail_types/oci`, `presentation/drivers/oci`, and `infra/docker`
   components, tagged `#paused`.
4. Add a new view (not folded into the existing layer-grouped Components view, to keep each
   view at one concern per c4lint's discipline) scoped to just the jail-type components across
   all three types, grouped by jail type rather than by layer, with zero edges drawn between
   any two types' components -- the visual proof of rule 3.
5. `likec4 validate` and c4lint clean; `just done` green.

### Risks

- Two orthogonal groupings (by layer, by jail type) over a growing but still partially
  overlapping set of components risks a cluttered single view; splitting into a second,
  narrower view (step 4) is the mitigation, not an afterthought.
- `infra/docker.py` sits in a different layer (infra) than the other two oci components
  (domain, presentation) -- the new view needs to show it as part of oci's slice without
  implying it is a jail-type-level concept the other two layers also have (rule 3 is about
  domain/jail_types and presentation/drivers specifically; infra/docker is oci-specific
  plumbing, not a fourth file every jail type needs).

### Proof

- `likec4 validate` clean, c4lint 0 errors.
- The new view visibly shows three separate clusters (bwrap, seatbelt, oci) with no inter-type
  edges.
- `just done` green.
