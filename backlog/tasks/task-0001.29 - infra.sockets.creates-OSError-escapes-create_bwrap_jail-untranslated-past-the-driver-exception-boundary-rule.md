## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-0001.26 wired `ChannelDirectoryPort.create` into `create_bwrap_jail`, inside its
existing `try`. A host filesystem failure there (a full disk, a permissions change
under brig's own state directory, `chmod` failing after `mkdir` succeeded) raises a
raw `OSError` straight out of `create_bwrap_jail` -- unlike every other call this
function makes into infra (`StateDirectoryInvalid`, `StateDirectoryUnreachable`,
`ChannelDirectoryUnreachable`, `JailSpawnFailed`), which all cross the
driver-exception-boundary rule into one of `presentation/errors.py`'s own types.

Found during TASK-0001.26's own implementation (its worker's report, 2026-10-25): the
task's plan named no typed error for this case, so it was documented in
`create_bwrap_jail`'s own docstring rather than invented on the spot -- this task is
that invention, done deliberately with its own plan and tests instead.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria

- [x] #2 An integration test, with a fake ChannelDirectoryPort whose create raises OSError, pins the translation
