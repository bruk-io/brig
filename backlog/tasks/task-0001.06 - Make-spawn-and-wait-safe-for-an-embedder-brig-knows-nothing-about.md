## Why

An adversarial review of the walking skeleton (TASK-0001.03) found two hazards in infra's process
primitives that only appear in an embedder brig cannot see, and that decision-0001 does not name:

- infra/processes.py spawns with os.fork() and then runs os.setsid(), os.chdir() and os.execvpe()
  in the child. None of those is async-signal-safe: os.execvpe is Python code that builds the
  environment and walks PATH, so in a multi-threaded embedder the child can block on a lock another
  thread held at fork time. The parent then blocks forever on its os.read() of the error pipe, and
  the public API hangs with a forked clone of the embedder's process alive. Python 3.15 already
  deprecates fork in a multi-threaded process. posix_spawn or vfork-style exec is the usual answer.
- infra/processes.py's reap is an untimed os.waitpid. A jailed process that never exits hangs the
  embedder forever, and no effect in domain/effects.py expresses a wait with a deadline, so no
  operation can give up. A sandbox whose subject can block the host program indefinitely is a
  denial of service in the primitive, separate from the teardown ladder's own grace period
  (step 4's "the teardown ladder in full").
